# Artint AutoPublisher

بوت Telegram لأتمتة جمع الأخبار من مصادر RSS، إعادة صياغتها عربيًا
بالذكاء الاصطناعي، فلترتها، ثم نشرها في قناة Telegram — تلقائيًا أو
بموافقة يدوية من المشرف.

---

## ⚠️ تعديلات معمارية مهمة عن المواصفات الأصلية (اقرأها أولًا)

طلبت المواصفات SQLite + Vercel Cron كل 30 دقيقة. هذان الأمران **لا يعملان
فعليًا على Vercel Serverless**، وتم تعديل التصميم بدل تسليمك كودًا لن يعمل:

1. **قاعدة البيانات: PostgreSQL بدل SQLite.**
   دوال Vercel لا تملك قرصًا دائمًا: كل استدعاء قد يعمل على حاوية جديدة،
   وقد تعمل عدة نسخ من نفس الدالة بالتوازي بدون ملف مشترك بينها. أي بيانات
   تُكتب في ملف SQLite ستضيع أو تتعارض. لذلك يستخدم المشروع PostgreSQL
   مُستضافًا مجانًا (Supabase أو Neon) عبر متغير `DATABASE_URL`. طبقة
   قاعدة البيانات معزولة بالكامل في `bot/database.py` كما طلبت، فتغييرها
   لاحقًا لا يمس بقية المشروع.

2. **الجدولة: GitHub Actions بدل الاعتماد فقط على Vercel Cron.**
   خطة Vercel المجانية (Hobby) تسمح بتشغيل Cron **مرة واحدة يوميًا فقط**؛
   أي جدول أكثر تكرارًا (كل 30 دقيقة مثلًا) يفشل عند النشر. المشروع يتضمن
   `vercel.json` بجدولة يومية كخط أمان يعمل مجانًا دون أي إعداد إضافي،
   بالإضافة إلى GitHub Actions مجاني (`.github/workflows/trigger-cron.yml`)
   يستدعي نفس المسار `/api/cron` بالوتيرة الفعلية التي تريدها (كل 15
   دقيقة كمثال، وقابل للتعديل). كلاهما يستدعي نفس الكود، فالمنطق البرمجي
   لم يتغير، فقط "من يقرع الجرس".

3. **لا Application دائم من python-telegram-bot.**
   إصدارات المكتبة الحديثة async بالكامل ومصممة لعملية طويلة العمر. على
   Serverless نُنشئ كائن `Bot` وننادي `initialize()`/`shutdown()` في كل
   استدعاء، وهذا هو الأسلوب الرسمي الموصى به لاستخدام المكتبة بدون
   Application — يحافظ على استخدام المكتبة و Webhook كما طلبت.

باقي المواصفات نُفذت كما هي.

## هيكل المشروع

```
artint-autopublisher/
├── api/
│   ├── webhook.py      # يستقبل تحديثات Telegram (GET فحص / POST Webhook)
│   └── cron.py         # يشغّل دورة RSS -> AI -> فلترة -> نشر
├── bot/
│   ├── config.py        # قراءة متغيرات البيئة والثوابت
│   ├── database.py       # طبقة PostgreSQL بالكامل
│   ├── telegram_api.py    # لوحات المفاتيح + دوال إرسال Telegram
│   ├── sources.py        # جلب RSS
│   ├── ai.py             # إعادة الصياغة والتقييم بالذكاء الاصطناعي
│   ├── filters.py        # منع التكرار + حدود التقييم/الجدولة
│   ├── publisher.py       # تنسيق ونشر المنشور في القناة
│   ├── pipeline.py        # المسار الكامل الذي يستدعيه api/cron.py
│   └── handlers.py        # التعامل مع أوامر ولوحة تحكم Telegram
├── .github/workflows/trigger-cron.yml
├── requirements.txt
├── vercel.json
└── .gitignore
```

## 1) إنشاء البوت على Telegram

1. افتح محادثة مع [@BotFather](https://t.me/BotFather).
2. أرسل `/newbot` واتبع التعليمات لاختيار اسم ومعرّف (يجب أن ينتهي بـ `bot`).
3. سيعطيك BotFather **Token** — احفظه، هذا هو `BOT_TOKEN`.
4. أرسل رسالة لبوتك الخاص (أي رسالة) ثم افتح الرابط التالي في المتصفح
   لمعرفة رقم حسابك (Chat ID) — هذا هو `ADMIN_ID`:
   ```
   https://api.telegram.org/bot<BOT_TOKEN>/getUpdates
   ```
   ابحث عن `"from":{"id": ...}` في الرد.

---

## 2) إنشاء مفتاح OpenAI

1. أنشئ حسابًا على https://platform.openai.com
2. من صفحة API Keys أنشئ مفتاحًا جديدًا — هذا هو `OPENAI_API_KEY`.
3. يمكنك استخدام أي نموذج تختاره عبر متغير `OPENAI_MODEL` (الافتراضي
   `gpt-4o-mini`)، أو الإشارة لواجهة متوافقة أخرى عبر `OPENAI_API_BASE`.

---

## 3) إنشاء قاعدة بيانات PostgreSQL مجانية (Supabase)

1. أنشئ حسابًا على https://supabase.com (يعمل من متصفح الجوال مباشرة).
2. أنشئ مشروعًا جديدًا (اختر كلمة مرور قوية لقاعدة البيانات).
3. من Project Settings -> Database -> Connection string، انسخ رابط
   الاتصال بصيغة `postgresql://...` — هذا هو `DATABASE_URL`.
   (بديل: https://neon.tech يعمل بنفس الطريقة تمامًا).

---

## 4) رفع المشروع إلى GitHub من الجوال

أسهل طريقة من الهاتف:

1. أنشئ مستودعًا جديدًا فارغًا على github.com باسم `artint-autopublisher`.
2. من صفحة المستودع اضغط **Add file -> Upload files**.
3. ارفع كل ملفات المشروع (حافظ على نفس أسماء المجلدات: `api/`, `bot/`,
   `.github/workflows/`) — متصفح الجوال الحديث (Chrome/Safari) يدعم رفع
   عدة ملفات دفعة واحدة من تطبيق الملفات.
4. اكتب رسالة Commit ثم اضغط **Commit changes**.

---

## 5) ربط المشروع بـ Vercel ونشره

1. أنشئ حسابًا على https://vercel.com وسجّل الدخول بحساب GitHub نفسه.
2. اضغط **Add New -> Project** واختر مستودع `artint-autopublisher`.
3. Vercel سيكتشف تلقائيًا أنه مشروع Python. لا حاجة لأي إعداد إضافي.
4. **قبل الضغط على Deploy**، افتح قسم **Environment Variables** وأضف:

   | المفتاح | القيمة |
   |---|---|
   | `BOT_TOKEN` | التوكن من BotFather |
   | `ADMIN_IDS` | رقمك (أو أكثر من رقم مفصول بفاصلة) |
   | `OPENAI_API_KEY` | مفتاح OpenAI |
   | `DATABASE_URL` | رابط Supabase/Neon |
   | `CRON_SECRET` | نص عشوائي طويل من اختيارك (16 حرفًا فأكثر) |
   | `WEBHOOK_SECRET` | نص عشوائي آخر (اختياري لكن يُنصح به) |

5. اضغط **Deploy**. بعد انتهاء النشر ستحصل على رابط مثل:
   `https://artint-autopublisher.vercel.app`

---

## 6) ربط Webhook بـ Telegram

افتح هذا الرابط في متصفح الجوال (استبدل القيم بين `< >`):

```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<DOMAIN>/api/webhook&secret_token=<WEBHOOK_SECRET>
```

يجب أن يظهر رد يحتوي `"ok":true`. إن لم تضبط `WEBHOOK_SECRET`، احذف
`&secret_token=...` من الرابط.

للتأكد أن الدالة تعمل، افتح مباشرة:
```
https://<DOMAIN>/api/webhook
```
يجب أن تظهر عبارة: `Artint AutoPublisher is running`

---

## 7) أول استخدام

1. أرسل `/start` لبوتك على Telegram — يجب أن تظهر لوحة التحكم.
2. أرسل `/setup` لعرض حالة الإعداد الحالية وأزرار مختصرة لإكماله.
3. من **📢 القنوات -> إضافة قناة**: أضف البوت كمشرف (Admin) في قناتك أولًا
   من إعدادات القناة على Telegram، ثم أرسل معرّفها للبوت (مثل
   `@ArtintDigital`).
4. من **⚙️ المصادر -> إضافة مصدر**: أدخل اسم المصدر ثم رابط RSS ثم اختر
   التصنيف.
5. أرسل `/test` للتأكد أن Telegram وقاعدة البيانات و RSS والذكاء
   الاصطناعي تعمل جميعًا بنجاح.
6. من **🤖 إعدادات الذكاء الاصطناعي**: اختر وضع النشر (تلقائي/موافقة
   يدوية)، والحد الأدنى للتقييم، وباقي الخيارات.
7. اضغط **▶️ تشغيل النشر** من القائمة الرئيسية.

---

## 8) تفعيل الجدولة المتكررة (كل 15 دقيقة مثلًا)

`vercel.json` يشغّل دورة تلقائية مرة واحدة يوميًا مجانًا بدون أي إعداد
إضافي (خط أمان). للحصول على وتيرة فعلية أسرع (كل 15-30 دقيقة كما طلبت):

1. في مستودع GitHub: Settings -> Secrets and variables -> Actions.
2. أضف Secret باسم `PROJECT_URL` بقيمة رابط مشروعك على Vercel.
3. أضف Secret باسم `CRON_SECRET` بنفس القيمة التي وضعتها في متغيرات
   بيئة Vercel.
4. ملف `.github/workflows/trigger-cron.yml` سيبدأ العمل تلقائيًا (يمكنك
   تعديل `*/15 * * * *` لأي وتيرة تريدها).
5. للتشغيل الفوري اليدوي: من تبويب **Actions** في GitHub اضغط
   **Run workflow**.

يمكنك أيضًا اختبار المسار يدويًا من متصفح الجوال:
```
https://<DOMAIN>/api/cron?secret=<CRON_SECRET>
```

## استكشاف الأخطاء

- **لا يرد البوت على /start**: تأكد أن `setWebhook` أعاد `"ok":true`،
  وأن رقمك موجود في `ADMIN_IDS` بالضبط.
- **"ليس لديك صلاحية"**: رقم `ADMIN_IDS` غير صحيح — تحقق منه عبر
  `getUpdates` كما في الخطوة 1.
- **لا يحدث نشر تلقائي**: تأكد من ضبط قناة افتراضية، وأن وضع النشر
  `تلقائي`، وأن ▶️ تشغيل النشر مفعّل، وأن الجدولة (الخطوة 8) تعمل فعليًا.
- افحص السجلات (Logs) من: Vercel Dashboard -> مشروعك -> Deployments ->
  اختر آخر Deployment -> Functions.
